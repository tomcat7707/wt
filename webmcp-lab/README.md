# WebMCP 쇼핑 실험실

이번 실험은 WebMCP가 단순한 ON/OFF 예제보다 실제 웹서비스에서 어떤 느낌인지 이해하기 위한 작은 미니 쇼핑몰입니다.

## 사람과 Agent가 같은 쇼핑몰을 사용한다

사람은 상품 카드의 **장바구니 담기** 버튼을 누릅니다.

Agent는 WebMCP Tool을 사용할 수 있습니다.

- `search_products` — 상품 검색
- `add_to_cart` — 상품을 장바구니에 추가
- `remove_from_cart` — 장바구니에서 상품 제거
- `get_cart` — 장바구니와 총액 조회

모든 Tool은 이 페이지의 JavaScript 함수와 연결되어 있으므로, Agent가 Tool을 호출하면 사람이 보는 상품/장바구니 화면도 함께 바뀝니다.

## 추천 실험

1. 페이지를 새로고침합니다.
2. WebMCP Inspector에서 Tool 목록을 확인합니다. 이제 4개가 보여야 합니다.
3. `search_products`에 `텀블러`를 넣어 실행합니다.
4. `add_to_cart`에 `product_id: "tumbler"`, `quantity: 1`을 넣어 실행합니다.
5. 브라우저 화면의 장바구니가 실제로 바뀌는 것을 확인합니다.
6. `add_to_cart`로 `coffee` 1개와 `cookie` 1개를 더 담아 봅니다.
7. `get_cart`를 실행하면 상품금액, 배송비, 총액이 구조화된 데이터로 반환됩니다.

가능하면 Inspector의 Gemini 기능으로 다음과 같이 자연어 요청도 시험해 보세요.

> "텀블러 하나 찾아서 장바구니에 담아줘."

또는

> "원두와 쿠키를 각각 하나씩 장바구니에 담고 총액을 알려줘."

## 이번 실험에서 봐야 할 것

핵심은 **AI가 화면의 버튼을 찾아 클릭하는 것이 아니라 웹앱이 Agent에게 제공한 기능을 직접 호출한다는 점**입니다.

사람의 경로:

`사람 → 상품 버튼 → 장바구니`

Agent의 경로:

`Agent → add_to_cart Tool → 장바구니`

그리고 두 경로의 결과는 같은 웹페이지에 나타납니다.

## 중요한 제한

이것은 실제 쇼핑몰이 아닙니다. 결제, 로그인, 외부 주문은 없으며 모든 데이터는 브라우저 메모리에서만 유지됩니다.

이 실험이 이해되면 다음 단계에서 `get_zone_status()`, `request_irrigation()` 같은 NeoFarm 기능을 같은 방식으로 설계할 수 있습니다.
